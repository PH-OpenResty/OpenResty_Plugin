# CNB issue #2 与既有审查的独立复审

复审基线为 `e90a0c87eb0c6d8e2d9248ee99d50999fbd551a4`。输入包括 [CNB issue #2 的正文和全部讨论](https://cnb.cool/Neko_Kernel/Neko_New/OpenResty_Plugin/-/issues/2)、其关联 #3–#10，以及既有 Sync/Ban/Tier/Purge 审查的隔离复现。CNB 分析使用的仓库提交为 `3d3459e6d27b6d8e683f11428ffc48c37f9dab2b`，报告自身声明没有 C 编译器；本次逐项检查当前调用链，并补充实际 Nginx、Master/Node、SQLite 和 eBPF 回归。

报告中“模型切换成功”无法从源码证明，本复审只使用其技术结论与证据。测试不访问生产节点或真实模型供应商。完整测试结果另见 [验证记录](validation-audit-20261116.json)。

## 确认并修复的正确性与恢复问题

| 来源 | 当前复审结论与修复 |
| --- | --- |
| 既有 Sync：未确认的终态回执被淘汰 | 成立。网络的 `X-Task-Lease` 表示 attempt，未赋值的本地 lease 原为 0，导致未确认收据进入 GC。执行前持久化非零保留标记，仅在 Master ACK 成功后清零。真实 120 秒租约和 128 条容量压力验证同一刷新只执行一次。 |
| 既有 Sync：更换 scope 后复用旧密文 | 成立。旧包复用原来只检查 payload 和期限。现在同时核对 Node/scope、当前 sequence、mTLS 指纹、RSA 加密公钥与签名公钥；相同正文的 scope/密钥变更也产生新序号。 |
| #8：sequence.state 丢失 | 部分成立。原实现已在残留 desired.bundle 时报告 `sequence_missing`，并不会直接覆盖为 1。现在仅从当前签名密钥验证成功的 desired.bundle 恢复序号下界，随后递增发布；损坏 state 仍拒绝，不降低 Node 水位。两份文件都丢失或整套备份回退仍须恢复可信备份，不能自动猜测远端水位。 |
| 既有 Ban：远端解封没有本机事件时间屏障 | 成立。将签名快照的 UTC 水位转换为本 boot 的事件截止时间，旧排队事件可持久确认但不能复活封禁；清理旧证据和早于水位的本机记录。同一水位不会随重复同步不断向后移动。 |
| 既有 Ban：跨 boot 保留旧 BOOTTIME 水位 | 成立。更换 boot 时清空只属于旧 boot 的事件、证据和单调水位；旧 boot 事件仍由事件身份检查拒绝，新事件可以重新形成封禁。 |
| 既有 Ban：重启时 UTC 回拨延长封禁 | 成立。保存恢复检查点；换 boot 时重建期限受原始时长、UTC 期限及最后持久化的剩余单调时间约束。完整快照的剩余期限也不超过原始时长。无法证明停机期间的实际时间时采用保守上界，不把时钟回拨变成额外小时。 |
| 既有 Ban：日志积压导致多次启动失败 | 成立。单次投影原来最多 256 条后抛出 `log_backlog`。现在顺序读取有容量上限的 audit 表并完整投影，两份日志的校验/fsync/游标均保留；800 条可恢复积压一次启动成功。 |
| #7：自定义缓存配置遗漏早期 Tier 变量求值 | 条件成立。标准模板通过动态 `proxy_cache` 和 key 提前安装回调；静态 backend zone/key 可以推迟该时机。现在缓存 HIT 未捕获原始绝对期限时继续服务 L2，但明确禁止向 L1 晋升，避免赋予新的相对 TTL。 |
| #6：重复请求头 | 一次遍历优化同时修复只读取首个 Cache-Control/Pragma/Accept 的问题。所有重复字段参与判断，后续 no-store/no-cache 不能被前一个 public/无关值掩盖。 |

## 资源开销与防御性修复

| 条目 | 修改与仍存在的边界 |
| --- | --- |
| #4：固定 256 站点快照 | sites 改为按实际数量增长的数组，空配置不分配站点数组；单站点不再内嵌整个最大表。最大站点/Host/route 数保持原限制。旧请求仍持有各自快照，不能把任意并发下的内存简单等同于“两份”。 |
| #4：每轮完整解析/证书对象构建 | 增加内容相等路径，仍完整读取和哈希源文件及证书/私钥；相同内容复用不可变快照，检查证书期限与目录有效性。保留同大小、同 mtime 内容替换检测，不以 stat 代替内容验证。多 Worker 的内容读取成本仍然存在。 |
| #4：每请求三次全局锁、重复 applied 写 | 通过共享原子 generation 判断稳定版本；未变化时直接引用 Worker 本地不可变快照，切换时一次锁内核对并更新 applied。版本对象和 OpenSSL 引用释放均移到锁外。 |
| #4：5 秒固定新鲜度阈值 | 调整为 `max(5s, 3 × interval)`，同时用于提交和全 Worker ready。仍检查 PID；后台/状态路径中的 kill 系统调用有 Worker 数量上限。 |
| #4：私钥和源文件权限 | 拒绝 group/other 可写的配置/证书，私钥拒绝任何 group/other 权限。加载失败保留已有路由和 TLS。目录与读取身份仍由部署者正确配置。 |
| #5：每请求全局 counter 查找 | 增加有界 Worker 本地 counter 缓存，常用站点复用稳定共享指针；未命中时保留有锁的创建/完整 ID 比较。显式检查 ID 长度，并在写完 ID 后增加可见 count。 |
| #5：Host 线性扫描 | 快照准备时构建排序 Host 索引，请求和 TLS 查找改为二分；实际验证 256 个站点、8,131 个 Host、大小写和未知 Host。最长 URI 前缀仍在每站点至多 32 条中查找。 |
| #5：HTTPS 示例 | Edge-only 示例补齐 Host、SNI、证书链校验、CA 和验证深度；关闭可变身份的 TLS session reuse。使用 API 模块时还可采用其按连接身份检查的池模板。 |
| #5：指标缓冲 | 按实际 counter 数量和 ID 长度计算有界输出缓冲，不再固定每条预留 4KiB。 |
| #6：请求头反复扫描 | 常规分类改为一次遍历，且 `headers_done` 在扫描前返回；有界正文检测仍保留。 |
| #2/#8：Sync 固定大缓冲及重复构建 | 规范文本、payload、下载与路径重定位缓冲按实际内容增长/分配。Master 只保留一份最近 source 的快照/payload 缓存；内容相同时跳过重解析和封装，不为 256 个 source 各自常驻一个 16MiB 缓冲。轮换 scope 仍可能重建。 |
| #8：逐 peer 反复读取大包并验签 | 已验证对象缓存绑定 payload、身份/密钥和 sequence，并检查持久文件的 inode/size/mtime/ctime。文件或任一绑定改变后重新验证；状态损坏仍拒绝。公钥读取、状态核对和目录操作仍有界地随 peer 数增长。 |
| #2/#8：probe 和 active_wait | 业务探测改为最多四路并发，保留原来每项 3 秒、1MiB、禁止重定向的边界；并非原报告所述每项 10 秒。活动确认轮询从 50ms 退避到 800ms，新增 1s–10m 的 `scdn_sync_config_apply_timeout`，默认仍 15s。 |
| 既有 Ban：每个 HIT/过时事件全量 reconcile | 仅变更回执或证据且无历史执行/日志错误时省略全量内核/视图/日志重建；实际封禁变化仍同步处理，周期 tick 继续重试未完成工作。ACK 仍表示持久记录。 |
| 既有 Purge：64 项 regex cache 小于单 scope 128 规则 | 缓存容量对齐 128 规则上限，消除同一 scope 的 65–128 条规则顺序扫描反复编译。多 scope 工作集大于缓存仍可淘汰，不声称任意规模零编译；PCRE 字节码、匹配步骤、深度和堆预算保留。 |
| #10：防御性边界 | wildcard 函数自行拒绝尾部裸反斜杠；Purge 空 token 明确拒绝；Sync 本地持久 lease 超出正常未来窗口时报损坏；X-Config-Managed 验证完整小写十六进制。 |
| #6/#7/#10：本机状态响应 | Edge/API metrics 与 Tier status 补 `Cache-Control: no-store`；Config status 原来已经有该头。身份边界保持各接口明确的实际 Socket/loopback 与文件系统权限。 |

| #2：token 长度短路可逐字节泄漏/DoS | 长度不保密，等长内容比较保持完整 XOR。报告也未给出可利用路径；不增加固定 128 字节填充造成新的截断或长度约束。 |

| #5：未知 Host 绕过管理端点 | 当前 403 是业务 server 的默认安全边界。管理端点按示例放独立受限 server；未新增猜路径自动绕过路由、WAF 或 Ban 的规则。 |
| #4/#5/#7/#10：共享热度、后台锁、kill 与任务扫描 | MD5 在这里用于有界表索引，不承担密码学认证；全局计数需要并发同步。TASK_NEXT 只遍历未移走的 .task，终态记录会移到 .done，不是每轮重读全部历史终态任务。仍有 128 条、64KiB 的队列最坏扫描成本；Purge journal/flock 保留事务顺序，不以取消锁换取未经证明的吞吐。 |

## 升级与验证

Config 的快照 C 布局发生改变，必须从同一提交完整重编译所有模块，停止旧进程后统一启动，不能只替换一份动态模块。生产更新前保留模块、Nginx 配置、站点/证书、Sync 状态和 Ban 数据库的一致备份。本次只交付源码与隔离测试，不更改生产部署。

历史 lease=0 的终态回执不能仅靠本地文件区分“已经 ACK”与“ACK 丢失”。升级前应让 Master/Node 在正常连通下完成在途任务并保留队列/收据备份；不要把旧回执当成新修复已经追溯验证的记录。

新增回归纳入三种 CI 构建：身份/scope/密钥与序号恢复、真实租约容量压力、索引和权限、静态 backend key 的安全晋升降级，以及时钟/水位/日志恢复。Nginx 构建继续执行 ASan/UBSan 和真实 TCX/XDP，OpenResty 继续执行保留 Lua WAF 联动。隔离复现与操作计数不是生产吞吐、内存峰值或 p99 容量保证。
