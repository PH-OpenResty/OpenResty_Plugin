## Bot 语义

已确认官方 IP 的条目使用 UA 与相应官方来源条件；没有确认官方 IP 的条目按用户要求保留 UA 分类和站点策略，标为 `ua_only`。UA 单独命中不提供可信身份、认证豁免或容量豁免。部分兼容 UA 尚待官方正文复核，`ua_evidence` 明确区别该状态，不伪装成已核验官方签名。

Brave 官方明确不提供独立爬虫 UA，伙伴型搜索也可能没有独立抓取身份。这些服务单列，不虚构 UA/IP 来宣称已覆盖所有搜索引擎。目录应允许增加本地规则和新提供者；不能自动把未知浏览器识别为某个搜索服务。

手工恶意规则及扫描器拒绝规则采用 UA **或** IP 任一命中，区别于搜索来源验证。Censys 的官方表为 16 个 IPv4、4 个 IPv6 前缀，官方 UA 为 `CensysInspect`。FOFA 的 `FofaBot` 仅为可配置候选，没有获得完整官方 UA/IP 清单，`coverage` 明确不完整；严格防护还需要源站访问边界及行为规则。

360 官方页面的六个 `a.b.c.*` 明确转换为对应 `/24`；Censys 从官方 Markdown 的网段代码块提取。其他表保留官方 JSON 的精确 CIDR，不把单个 `/32` 扩大成 `/24`，不推导整个 ASN。

Google 两份用户触发来源表仅作为分类数据保留，尚未将宽泛 UA 自动绑定到这些表；不能据此允许用户托管服务或任意 Google 网络绕过防护。完整的来源更新、有效期、签名分发和回退需要在实现中补齐。

## 弱密码使用边界

数据取自 SecLists 固定提交的 `10k-most-common.txt`，实际有 10,001 个非空不同条目，名称中的 10k 不替代真实计数。公开结果保存条目摘要，完整来源及数据摘要见 manifest；可按固定提交重复生成并逐项验证。

按整个候选密码精确匹配，不去首尾空白、不小写、不做 Unicode 归一化、不匹配子串。摘要只用于已知公开弱选择的成员查询，不用于保存用户认证密码或行为指纹。禁止记录用户输入口令及其可离线猜测的摘要。

实际消费者应在注册/修改口令时拒绝命中项，支持版本化本地扩展，避免联网发送候选口令。首次弱密码选择返回明确错误，不自动封禁 IP；达到明确注册滥用条件才触发 IP 处置。已有弱密码账号仍须能登录后完成修改。加密负载中的口令由可信后端解密后检查，不在 Nginx 引入私钥。
