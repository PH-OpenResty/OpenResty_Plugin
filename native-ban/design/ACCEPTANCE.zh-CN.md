# Ban v2 实施验收矩阵

状态：待实现用例。本表不代表已通过运行模块、内核丢包或生产验收。设计阶段仅检查结构、示例、ABI 和隔离共享视图原型。

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| E01 | 第一次可信 WAF_DENY | 当前请求拒绝；正式状态仅为对应站点 L7 |
| E02 | 确认 CC | 直接生成 L3 意图；确认包含实际内核结果 |
| E03 | 一个 WAF 事件加 N-1 个 L7_HIT | 恰好升级一次，窗口中每个主请求计一次 |
| E04 | 普通源站 403/429、业务鉴权失败 | 不产生 Ban 事件或自动封禁 |
| E05 | 同请求多规则、子请求、内部跳转 | 频率只加一；更强 CC 可升级动作 |
| E06 | 跨 Worker、跨实例乱序事件 | 按有效事件时间得到相同窗口结果 |
| E07 | IPC 重传、旧 seq、同 seq 改内容 | 不重复执行；冲突或过旧回执明确拒绝 |
| E08 | 解封后重放旧 L7_HIT ban_id | 不重新封禁或延长期限 |
| E09 | CC/规则未登记、客户端伪造头 | 不作为可信封禁事件 |
| E10 | fallback/影子拒绝或视图读取错误 | 不生成新的频率证据或重置封禁期限 |
| T01 | 封禁期间持续访问 | expires_boot_ns 不变 |
| T02 | 升级后 L3 到期 | 清除节点状态，不复活被取代的站点 L7 |
| T03 | 传输、同步或重试耗尽期限 | EXPIRED_BEFORE_APPLY，不重新起算 |
| T04 | wall clock 调整/系统休眠 | 同 boot 期限以 BOOTTIME 正确执行 |
| T05 | Agent 停止且条目未被 GC | 内核与旧视图仍在固定期限后停止该 IP 封禁 |
| T06 | Nginx/Agent 重启 | 恢复原 ban_id/期限，旧视图 inode 可继续使用 |
| T07 | 整机重启、UTC 未就绪 | 不使用旧 BOOTTIME，不重置整个 TTL |
| T08 | 解封/轮次结束后收到迟到事件 | 重置点之前的证据不重新计入或立即复活封禁 |
| V01 | Worker 只获得只读 FD | 写入、可写映射和重新打开为写均被 UID/权限拒绝 |
| V02 | Agent 中断在非活动 bank 写入 | 活动记录仍完整，不永久处于 seqlock odd 状态 |
| V03 | 并发重复发布、读者暂停后恢复 | 不接受混合字段；3 次不稳定后明确 503 |
| V04 | Agent 重新打开共享文件 | 不 unlink/truncate；原读者立即看到后续更新 |
| V05 | 槽冲突/活动容量满 | 拒绝新申请，不驱逐已有有效记录 |
| V06 | 视图尺寸、偏移、版本、所有者异常 | 不映射未知布局；不能作为空黑名单放行 |
| P01 | 截断/超长帧、未知类型、非零保留位 | 有界拒绝，FD 不泄漏 |
| P02 | 伪造 UID/instance，错误 namespace FD | 不登记生产者、不执行变更 |
| P03 | 时间过旧、未来时间、跨 boot | 拒绝且不重新赋予当前时间 |
| P04 | Worker 队列、请求去重或回执表满 | 明确背压，不能伪报持久/生效 |
| K01 | IPv4/IPv6/IPv4-mapped IPv6 | 键一致，跨站点 L7 隔离与 L3 节点范围正确 |
| K02 | Web TCP/UDP 与自定义 LB 服务 | 只覆盖配置入口；非业务流量按策略继续 |
| K03 | 非首片、扩展头、截断报文 | 没有端口解析绕过；扩大到 VIP 的行为与策略一致 |
| K04 | VLAN/QinQ/offload/多缓冲区 | 覆盖能力报告真实，不静默改网卡参数 |
| K05 | 既有 XDP LB/TC 程序 | DROP 先于 redirect，未命中继续现有链 |
| K06 | Map 满、挂载/权限失败 | 不报告 L3_ACTIVE；保留原有效封禁 |
| K07 | 入站与已建立连接 | 不承诺未实现的出站丢弃或撤回已发响应 |
| K08 | 过期回收与新 ban_id 竞争 | GC/UNBAN 不删除后来的封禁 |
| L01 | PREPARE 同步前后 kill Agent | 未持久无正式确认；持久意图可幂等恢复 |
| L02 | Map 更新后、APPLIED 前 kill | 从 pin 与 PREPARE 对账，不伪造原执行时间 |
| L03 | 第二份 JSONL 文件写入失败 | LOG_PENDING、源 seq 可补投，无假成功 |
| L04 | WAL 半写尾与完整记录损坏 | 半写尾可恢复；完整校验错误拒绝继续变更 |
| L05 | 磁盘满/只读、旧日志恢复 | 有界失败、告警、不覆盖更新运行状态 |
| L06 | 日志轮转/归档/检查点 | 活动封禁和派生进度不丢失，不使用 copytruncate |
| C01 | TTL/阈值/规则热更新 | Worker 不重建；旧代际有效封禁继续执行到原期限，新窗口代际清晰 |
| C02 | 新增服务、豁免 | 覆盖变化有审计；移除豁免不复活旧 ban_id |
| C03 | 容量或 ABI 变更 | 明确维护需求，旧配置/视图仍有效 |
| C04 | Worker 死亡/恢复、Agent 失联 | 只读状态继续工作；未确认事件不冒充正式状态 |
| C05 | Sync/Master 断连 | 已有固定期限继续工作，新本机决策进入 outbox，恢复后核验最新完整表 |

性能分别测正常放行、封禁丢包、L7 命中、事件突发、冷/热表、容量边界和 WAL 同步竞争。报告 PPS/QPS、CPU、p99 决策至内核生效延迟、内存、队列及日志滞后，记录 NIC/驱动、接口模式、内核、CPU 和报文分布。相同基线和命中率下对比，不以关闭持久化或隐藏失败获取吞吐数字。

真实 DROP 验收在隔离 netns/veth 开始；真实节点启用前先观察、保存原 program/link/TC 状态和策略/日志恢复点，并验证只撤销本组件对象的回退流程。

## 集群全量同步必须新增的运行验收

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| S01 | Node A、Node B、Master 设备各产生不同 L3 IP | 所有登记节点最终持有同一完整有效集合，来源节点也接收 |
| S02 | WAF 首次 L7、升级 L3 | 首次保持站点 L7；升级后 L3 才进入全节点表 |
| S03 | 同 IP 多设备同时上报 | 合并为同轮全局 ban_id，不能由转发/命中延长期限 |
| S04 | 相同 seq/event_id 重传与改正文 | 同内容幂等确认；不同内容冲突 |
| S05 | 变更/初次加入/重连 | 下载并校验完整对象；不是仅补最后几条增量 |
| S06 | 快照为空、缺页、404、验签失败 | 仅验证成功的完整空表可对账清除；其余保留当前保护 |
| S07 | 旧 revision、相同 revision 改摘要、未知 epoch | 拒绝回滚/冲突/未知权威 |
| S08 | Node 离线期间其他节点封禁 | 集群为 PARTIAL，恢复后补齐最新全量，不能虚报全员完成 |
| S09 | 本机未上报封禁不在快照中 | 保留该本机意图，Master ACK 后再收敛 |
| S10 | 接收远程快照及内核 DROP | 不重新上报或进入升级窗口，无广播循环 |
| S11 | 时钟不可信、跨机重启、延迟超过 TTL | 明确拒绝确认/保持原期限；不复制其他 boot 的数值 |
| S12 | 全量中途 Map 满/日志失败/Agent kill | APPLY_FAILED/PARTIAL，不能清空旧表或伪报全量应用 |
| S13 | 人工全局解封后迟到 proposal/快照 | 墓碑/水位阻止复活，不删除后来新 ban_id |
| S14 | 单慢节点、坏来源、磁盘背压 | 其他节点继续收敛，坏来源不阻塞集群队列 |
| S15 | 节点 membership 变化与旧版 ACK | 当前目标集和 revision 清晰，旧版 ACK 不冒充当前 ALL_APPLIED |
| S16 | Master 双写/旧备份/切主 | fencing 及 authority_epoch 阻止两个权威和反重放水位倒退 |
| S17 | 快照超过预算 | 明确背压并保留当前表，不截断成“不完整全量” |
| S18 | 大表 N 节点高频变更 | 测量完整对象生成复用、带宽、CPU、p99 收敛和受限合并窗口 |

本表仍是待实现验收，不把 Schema/ABI 校验称作以上多机运行测试通过。
